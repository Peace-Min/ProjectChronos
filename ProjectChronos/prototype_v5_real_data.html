실제 시스템 변수명 기반 — 카드 레이아웃 해법 비교

✕ 현재 상태 — Label:Value 인라인, TextWrapping=Wrap
라벨(`dRangeBtwPlatformAndTarget`)과 값 모두 시스템 변수명이라 전부 wrap 발생
해법 A — Label/Value 2행 분리 + 둘 다 NoWrap 부분 해결
라벨과 값을 각각 한 줄씩 차지. 둘 다 NoWrap + 말줄임(…). 라벨이 잘릴 수 있음
해법 B — 2열 Grid (축약 라벨 | 값) 부분 해결
라벨을 축약 키("desc", "range", "src")로 줄이고 Grid 좌측에 고정. 값이 우측 전체 사용
★ 해법 C — 축약 뱃지 + 시스템명 전체 표시 완전 해결
라벨을 초소형 뱃지 태그(DESC/RANGE/SRC)로 축소 → 전체 가로폭을 시스템 변수명/값에 할당
핵심 차이 — 실제 데이터의 특수성:
이전 프로토타입의 시나리오 데이터는 라벨이 한국어 2~4글자("설명", "타겟간 거리")였으나,
실제 데이터에서는 라벨 자체가 시스템 변수명 (dRangeBtwPlatformAndTarget = 26자, ~280px)입니다.

해법별 판정:
• 해법 A: 라벨이 잘리지만 값은 살릴 수 있음. 라벨의 정보 손실이 있을 수 있음
• 해법 B: 라벨을 축약어로 사전 매핑 필요. 매핑이 있으면 깔끔하지만, 새 필드 추가 시 매핑 관리 부담
• 해법 C (★ 권장): 라벨을 최소 뱃지(DESC/RANGE/SRC)로 줄이고, 시스템 변수명 자체를 '값'으로 표시. 가장 공간 효율적이며 어차피 연구자에게 중요한 것은 변수명 자체이므로 정보 손실 없음
